📌 1. What this app is

FIRE is a personal investment tracker for one user (you) — a Python port of a Flutter app — where everything is stored in local CSV files. No login, no database, no cloud.

What it does

  • Fetches live ETF market data from a Google Apps Script API
  • Tracks your current holdings & sell history
  • Recommends ETFs to buy (deepest dip vs 20-day moving average)
  • Flags holdings as 🟢 Sell or 🔴 Buy-more candidates
  • Auto-computes every Kotak charge on each trade
  • Generates realized P/L reports

What it doesn't do

  • No broker integration — you execute trades in the Kotak app and log them here
  • No multi-user support
  • No tax-optimization advice
  • No push notifications / scheduling

💡 5. Core concepts

ETF types

Equity

Broad-market ETFs — Nifty, Sensex variants.

Jewellery

Gold / Silver ETFs.

Stocks

Direct equity — Reliance, Bajaj Finance, etc.

Buy / Sell signals (Home page)

TabConditionMeaning
🟢 Sell CMP > avgPrice × (1 + sellProfitTarget%) In profit — consider selling
🔴 Buy more CMP < avgPrice × (1 − buyInDipThreshold%) In dip — consider averaging down
⚪ Others neither Hold

Suggestion algorithm

Goal: pick one ETF per asset type with the deepest dip vs 20-DMA — and don't suggest things you already hold. 
1. Group all ETFs by type: Equity, Jewellery, Stocks
2. Sort each group ascending by change20DmaVsCmp   (= biggest dip first)
3. Take top 5 from Equity, top 3 from Jewellery, top 3 from Stocks
4. Remove any ETF already in holdings
5. For each type, pick the one with the greatest dip
6. Suggested quantity  =  ceil(investment / 25 / CMP)

The /25 divisor is the original app's allocation heuristic — roughly 4% of total investment per pick.

↓

new row OR merge avg price:

↓

Sell flow

Pick holding → Sell action
↓
Enter sell price + qty
↓
compute_kotak_charges(value, type, "sell")
gross − brokerage − STT − exchange − SEBI − GST − dividend = net
↓
sell_holding(...)
↓
Append row to sells.csv
↓
Update holdings.csv
if full qty sold → drop row
else → new_avg = (old_avg×old_qty − price×sold_qty) / (old_qty − sold_qty)
↓
Update user.csv
remaining += (value − charges − dividend)
investment += ((sell − avg) × qty − charges − dividend)

Reports computation

MetricFormula
Portfolio %(currentValue − costBasis) / costBasis × 100
Profit/Loss (gross)Σ (sellPrice − avgPrice) × qty
Growth (net)Σ [(sell − avg) × qty − brokerage − tax − dividend]
Total TaxΣ sells.tax
Total BrokerageΣ sells.brokerageCharges

▶️ 10. How to run

cd python_version
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py

Open http://localhost:8501

First-run checklist
  1. Open ⚙️ Settings → set your total investment → Save.
  2. Go to 💡 Suggestions → see top picks → click Buy.
  3. Home shows the holding; when CMP moves, it'll appear in 🟢 Sell or 🔴 Buy-more automatically.

⚠️ 12. Known simplifications

  1. Avg price ignores buy-side charges. Kotak shows traded avg the same way. Buy charges are deducted from remainingAmount and investment instead. Cost-basis P/L is slightly under-reported by buy fees (tiny for ETFs, small for stocks).
  2. Single-user only — no login, no isolation.
  3. ETF data freshness depends on the upstream Google Apps Script.
  4. No retry / offline queue — if API is down on startup, we fall back to cached CSV.
  5. Holdings > 20 warning is a soft UX nudge, not enforced.
