📌 1. What this app is

FIRE is a single-user investment tracker for Kotak Securities customers. All data lives in Firebase Firestore. Access is protected by an HMAC-SHA256 session token — one password, sessions last 7 hours.

What it does

  • Fetches live ETF market data from a Google Apps Script API
  • Tracks current holdings, buy history, sell history
  • Recommends ETFs to buy (deepest dip vs 20-DMA)
  • Flags holdings as 🟢 Sell or 🔴 Buy more candidates
  • Auto-computes every Kotak Securities charge per trade
  • Tracks Demat AMC charges monthly
  • Full ledger reconciliation in Reports page
  • Deposit / withdrawal / cashflow tracking

What it doesn't do

  • No broker integration — log trades manually after executing in Kotak app
  • No multi-user support
  • No tax-optimization advice
  • No push notifications or scheduling
  • DP charges and STT on equity sells are not yet auto-tracked (logged separately via Charges tab)

💡 5. Core concepts

ETF types

Equity

Broad-market ETFs — Nifty, Bank Nifty, Pharma, IT, Realty, PSU variants.

Jewellery

Gold & Silver ETFs — HDFC Gold, SBI Gold, Nippon Silver, etc.

Stocks

Direct equity — Reliance, Bharti Airtel, and other individual stocks.

investment vs remainingAmount vs totalDeposited

FieldWhat it meansChanges when
totalDeposited Cumulative bank deposits — the raw money you put in Only on deposit / withdrawal via Settings
investment totalDeposited + Σ net realized P&L — your effective buying power after all sells On every sell: increases by profit, decreases by loss
remainingAmount Liquid cash right now — what you can spend on the next buy Decreases on buy + AMC; increases on sell proceeds

Buy / Sell signals (Home page tabs)

TabConditionMeaning
🟢 Sell CMP > avgPrice × (1 + sellProfitTarget / 100) Holding is in profit — consider selling
🔴 Buy more CMP < avgPrice × (1 − buyInDipThreshold / 100) Holding is in a dip — consider averaging down
📋 All Holdings all holdings regardless of signal Default view; sorted by |P/L %| descending

Suggestion algorithm (💡 Suggestions page)

Goal: pick one ETF per asset type with the deepest dip vs 20-DMA that you don't already hold. 
1. Group all ETFs by type: Equity, Jewellery, Stocks
2. Sort each group ascending by change20DmaVsCmp   (biggest dip first)
3. Take top 5 Equity + top 3 Jewellery + top 3 Stocks candidates
4. Remove any ETF already in holdings
5. Pick the top-dip ETF from each type → "Fresh picks"
6. Also show ETFs already held that are in the deepest dip → "Buyback" candidates
7. Suggested quantity = ceil(investment / 25 / CMP)   (~4% allocation heuristic)

Weighted average price (on buy)

new_avg = (old_avg × old_qty + price × qty) / (old_qty + qty)

Average price is not adjusted when you partially sell — it stays at the last buy-weighted average until you buy more.

Realized P&L on sell

gross_pl   = qty × (sell_price − avg_buy_price)
net_pl     = gross_pl − brokerage − tax − dividend_paid_to_self

The investment field is updated by +net_pl on every sell.

Demat AMC auto-deduction

Every time the app starts, if today − lastAmcDate ≥ 30 days, the configured amcAmount (default ₹18.88 = ₹16 + 18% GST) is automatically deducted from both investment and remainingAmount, a record is written to the charges collection, and lastAmcDate is updated.

📑 8. Page walkthrough

🏠 Home

Portfolio overview: 3 allocation cards (Equity / Jewellery / Stocks) showing cost basis, current value, and unrealized P/L. Holdings split across 3 tabs:

  • 📋 All Holdings — default view, sorted by |P/L %| descending
  • 🟢 Sell — above profit target
  • 🔴 Buy more — below dip threshold

Each holding card shows avg price, CMP, qty, cost, value, P/L, and weighted-average hold time computed per lot from actual buy records. Inline sell and buy-more forms open on click. Recent activity (last 5 buys + sells) shown at top using paginated Firestore fetch.

💡 Suggestions

Pre-computed buy suggestions in two groups:

  • Fresh picks — ETFs you don't hold with the deepest 20-DMA dip
  • Buybacks — ETFs you already hold that are in the biggest dip

One card per suggestion showing ETF name, type, CMP, dip %, and suggested quantity. One-click buy opens the buy dialog pre-filled.

📋 Listed ETFs

Browse all ETFs fetched from the API. Filter by type (All / Equity / Jewellery / Stocks), search by name. Table sorted by 20-DMA dip descending. Shows CMP, 20-DMA, dip %, daily change %, and volume averages. Click any row to open buy dialog.

🔄 Transactions

Four-tab paginated transaction log:

  • Buys — all buy records with charges
  • Sells — all sell records with gross/net P/L
  • Charges — AMC and other non-trade charges
  • Cashflow — deposits and withdrawals

Date range filter applies across all tabs. Pagination uses Firestore cursor-based queries (start_after + count aggregation).

📜 Sell History

All past sells with formula-style cards showing gross P/L, charges breakdown, and net P/L per transaction. Date range filter. Running totals (total gross, total net, total fees) shown at top. Supports sell reversal — re-adds qty back to holdings and adjusts user balances.

📊 Reports

5-chapter storytelling layout — all data loaded from meta/stats in one read:

  • Chapter 1 — The headline: deployed capital, current direction (up/down), total return %, sub-line with holdings · cash · avg hold days
  • Chapter 2 — How the money is working: two panels — "Still in market" (cost basis → worth now → unrealized P/L) and "Already sold" (gross sold → net profit)
  • Chapter 3 — What it cost you: total fees sentence, 3 cards (buy fees, sell fees, demat AMC), collapsible full breakdown
  • Chapter 4 — Verify the totals: ledger reconciliation (expected vs actual balance, ✓/✗ with one-click fix)
  • Chapter 5 — Month by month: collapsible table of buys, sells, fees, net flow per month

⚙️ Settings

Sections: Appearance (theme toggle), Profile, Capital (investment + remaining cash), Thresholds (sell target, dip threshold, dividend %), AMC config. Three action tabs: Deposit, Withdraw, Add Manual Charge. Maintenance section at bottom with two admin actions: Rebuild stats (full rescan to rebuild meta/stats) and Backfill holding days (stamps holdingDays on existing sell records).

ℹ️ Info

Renders this documentation file (DOCUMENTATION.html) inside a scrollable iframe. Anchor clicks scroll within the iframe — they don't reload the Streamlit app. Edit DOCUMENTATION.html to update the in-app docs.

Sidebar (always visible): 🔥 FIRE brand + version badge · navigation radio · 🔄 Refresh ETFs button + last-fetched timestamp · Quick Stats card (deposited, after profit/loss with pill badge, cash in hand).

⚠️ 12. Known simplifications

  1. Average price ignores buy-side charges. Cost basis P/L is slightly under-reported by buy fees. This matches how Kotak displays traded average.
  2. DP charges not auto-computed. Kotak deducts ₹27 min / ISIN / day on delivery sells. These must be logged manually via Settings → Add Manual Charge, or the app balance will run slightly higher than the actual Kotak balance over time.
  3. Single-user only. One password, one Firestore project.
  4. ETF data freshness depends on the upstream Google Apps Script — if it's down, the app falls back to the local cache file.
  5. No retry / offline queue — Firestore writes fail loudly; there's no local queue for offline operation.
  6. No STT tracking on equity stock sells — the charge is computed and deducted from remaining amount, but not tracked in a separate line for tax filing purposes.
  7. Holdings > 20 warning is a soft UX nudge in Reports; not enforced.

📊 13. Kotak Audit Tool

kotak_audit.py is a standalone script that cross-checks FIRE's Firebase data against Kotak's official Excel exports — no internet needed. It detects missing charges, mismatched trades, and balance gaps, and maintains a history of every audit run.

Step 1 — Download Kotak reports

Log in to Kotak Securities → Reports and download two files. Save both into the reports/ folder inside the FIRE project directory.

📒 Ledger Report

Menu: Reports → Ledger
Select FY 2026–27 (full year).
File saves as: Ledger_V4SF4_YYYYMMDD_YYYYMMDD.xlsx

📋 Transaction Statement

Menu: Reports → Transaction Statement
Select the quarter to audit (e.g., Jul–Sep).
File saves as: Transaction_Statement_V4SF4_YYYYMMDD_YYYYMMDD.xlsx

Step 2 — Run the audit

cd /Users/ravi/Desktop/FIRE
python3 kotak_audit.py

The script auto-detects the latest Ledger and Transaction Statement files in reports/. It connects to Firebase, runs 6 checks, saves results to reports/audit_log.json, generates an HTML report, and opens it in the browser.

First run: checks demat charges from the beginning of history.
Subsequent runs: only checks new demat entries since the last audit date (incremental).

What the 6 checks do

💰 Deposits

Compares total deposits/withdrawals in Kotak ledger vs app's totalDeposited. Excludes cashflow entries that happened after the Kotak report's closing date.

🏦 Demat Charges

Finds every AMC and DP charge in the ledger's Demat section and checks whether a matching entry exists in the app's charges collection. Flags anything missing.

📥 Buy Transactions

Matches each Kotak buy by price + date (±5 days). Handles multi-lot: if you entered one Kotak trade as two app records, it sums quantities and still calls it matched.

📤 Sell Transactions

Same as buys — matches Kotak sells to app sell records by price + date proximity. Reports missing or qty-mismatched sells.

⚖️ Balance vs Kotak

Compares Kotak's ledger closing balance vs app's remainingAmount. Adjusts for post-report transactions so a fresh deposit or buy doesn't look like a gap. Gap ≤ ₹5 is a WARN (rounding); above ₹5 is a FAIL.

🔄 Internal Reconciliation

Verifies the internal accounting identity: remainingAmount + costBasis = totalDeposited + sellNetPL − charges. A non-zero drift here means rebuild_stats() needs to be run.

Reading the output

Each check shows a badge: PASS / WARN / FAIL. Any issues are listed as Action Items with IDs like 1-1, 1-2.

The HTML report also shows all previous audits in a history dashboard — you can see date, status, and balance gap across every run.

After fixing an issue

Once you've fixed a flagged item in the app (e.g. added a missing DP charge), mark it done so it doesn't show as pending on the next report:

python3 kotak_audit.py --mark-done 1-1 1-2

Other commands

Command What it does
python3 kotak_audit.py Auto-detect reports, run full audit, open HTML report
python3 kotak_audit.py --no-browser Same but don't open the browser (just save HTML)
python3 kotak_audit.py --history Print audit history table in terminal
python3 kotak_audit.py --mark-done 1-1 Mark action item 1-1 as done and regenerate HTML

Expected audit workflow (each quarter)

  1. Download Ledger (full FY) + Transaction Statement (the quarter) from Kotak → save to reports/
  2. Run python3 kotak_audit.py
  3. Review the HTML report — fix any FAIL items in the app
  4. Run --mark-done for each fixed item
  5. Run the audit again — confirm all clear

Known acceptable gaps

  • ₹2–3 balance gap — cumulative rounding from trade charge formula (app and Kotak both round to 2 decimal places per component, and the tiny errors add up over hundreds of trades). Not a missing transaction.
  • T+1 DP charges — Kotak posts DP charges the next business day after a Stocks sell. The date in the ledger may be 1 day after the sell date in the app. The audit allows ±3 days for demat charge matching.
